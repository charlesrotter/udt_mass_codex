# Maintaining the continuous development

UDT_DEVELOPMENT.md is the single maintained argument. The exact registry and
reviewed sources still own scientific grades; LIVE owns authorization and CANON
requires Charles's sign-off. This procedure does not supply physical premises.

For every accepted correction, clarification or new result:

1. Locate the affected definition/result in the central document before writing
   another report. Record the exact changed source/owner statement, old meaning,
   new meaning, hypothesis and scope. Keep the initial candidate and review history.
2. Run `python3 verify_udt_development.py`. Changed source/registry bindings fail
   with REVIEW_REQUIRED and flag recorded central descendants, including negative
   conclusions and contextual uses. The graph is bounded: also inspect the
   controlling sources for unrecorded dependencies. Absence of an edge is not
   evidence of independence. Do not refresh hashes to conceal an unreviewed change.
3. Reconsider affected arguments, not just labels. State what changes, what
   survives and why. A changed premise does not automatically refute every
   descendant. Never grandfather a negative conclusion more generously than a
   positive one. Update the existing central chapter, claim dispositions, source
   pins and typed graph. New optional inputs must remain visibly conditional;
   an open join or control cannot become an accepted premise.
4. Perform the checks appropriate to the actual change. Mathematical changes
   need substantive argument review and relevant independent checks. Packaging
   changes need version/routing/reproducibility review. Separate-context review
   is distinct from a different model or implementation. State omissions.
5. Freeze the proposed integration files. Both designated reviewers independently
   record their actual context, exposure, verdict, report path/hash, and identical
   accepted file hashes in FINAL_ATTESTATION.json. The parent REVIEW_RECORD.json
   binds those attestations. Updating an attestation is not itself review: there
   must be a corresponding actual review. Saving/committing remains separate from
   scientific acceptance. No automatic accept or hash-refresh command is supplied.
6. Regenerate CURRENT_RESEARCH_PROGRAM.md from the central orientation using
   `program_text` in verify_udt_development.py. LIVE/HANDOFF retain only status,
   permissions, pauses and the next gate; INDEX/MEMORY retain pointers. The registry
   guide explains grades. Do not maintain separate scientific explanations there.
7. Check `python3 verify_udt_development.py`, the matching adversarial guard
   tests, and `python3 verify_current_scientific_premises.py`. The full existing
   banking/registry checks remain authoritative regression requirements. Review
   staged bytes and preserve unrelated/protected files before committing/pushing.

The graph tracks central arguments D1/R1–R18, explicit conditions, source versions
and typed edges. Proof/hypothesis edges express stated dependencies; context and
interpretation edges conservatively route review without asserting logical
necessity. Registry dispositions route every row to its relevant discussion;
this is editorial coverage, not a reconstructed proof graph for all406 results.
RECENT_DISPOSITIONS.tsv covers the later reviewed work relevant to this account;
its entries retain source grades and reconstruction depth. Typed review_support
records preserve accompanying historical review/repair versions separately from
proof dependencies; changed support flags review without becoming a premise. A new package must
be added there or to the registry coverage when it becomes load-bearing.

`--draft` only checks construction coherence, excluding final review bindings.
It cannot satisfy the mandatory startup verifier. Tests use in-memory overlays;
original sources and registry are never edited to inject defects. Pins detect
changed bytes, not truth, honesty of reviewers, chronology or semantic completeness.
An intentional broader rewrite requires real review of the new argument and
hypotheses, not merely a passing string check.

The fixed through-G352 edition, consolidated account, original packages and
review manifests are historical evidence. They retain authentic paths/bytes.
HISTORICAL_EVIDENCE_INDEX.md is a frozen lookup catalog with repository-root links,
not a startup read or evolving scientific account. Earlier operational pages are
recoverable from grok26da433f; git is the rollback trail. No historical claim is
silently erased or rewritten to appear retrospectively corrected.
