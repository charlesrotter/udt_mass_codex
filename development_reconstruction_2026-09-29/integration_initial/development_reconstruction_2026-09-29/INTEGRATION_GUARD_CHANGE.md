# Guard migration scope

The former validate_startup_surface required repeated scientific and chronological
phrases in LIVE, HANDOFF, PROGRAM, MEMORY, INDEX and the premise guide. That forced
multiple maintained explanations. CDR1 replaces that duplication with mandatory
verify_udt_development.validate, a generated central orientation and strict
review/version bindings for the maintained account and all adapters.

The existing verifier still checks the 406 exact rows, original banking/source
proof limits, authority record, archived snapshots, startup order, method/skill
protocols, protected paths, historical quarantine and provenance. No package
validator or registry assertion is removed. The X_max semantic guard now examines
the central development in place of operational LIVE. Full audit must pass after
integration, not merely the smaller new guard.

The new guard checks exact disposition coverage/row versions, central source pins,
typed acyclic dependencies and explicit conditional inputs, later return versions,
central anchors, generated excerpt identity, actual independent review bindings,
and bounded known strengthening patterns. Strict adapter pins reject arbitrary
new science/stale advice until reviewed, including wording the patterns do not catch.
The adversarial tests separately exercise source and row changes, descendant
invalidation, missing conditional ancestry, cycles, open-premise promotion, stale
summaries, review mismatch and known semantic regressions. This is regression
coverage and correspondence, not an if-and-only-if semantic test.
