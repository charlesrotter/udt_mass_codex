# G279 lay report

The kernel passed the audit so far.

The simplest picture is that there are three layers:

1. **Native reciprocal core:** the metric says how the clock and ruler sides of a completed observer
   pair respond reciprocally, and it gives redshift directly through `phi`.
2. **Temporary light interface:** because UDT does not yet have its own light/flux theory, we openly
   import a transparent-transfer rule to translate that metric state into supernova brightness.
3. **Data reconstruction:** we use several finite numerical resolutions to estimate the area curve
   and then attach a conditional physical scale with Cepheid data.

The recent scale disagreement lives in layer 3. It does not reach backward and change layer 1.
Nothing in G278 secretly used P1, an old scaffolded kernel, `X_max`, a Lambda-CDM distance law, or a
late-added angular correction.

The angular orchestra is still native to the complete metric and enters before pair readout. It is
simply not needed for the direct SNe redshift calculation, and the G278 program does not calculate
the angular channel.

One label in the initial G278 ledger was too broad: it suggested the newer projective W5 position
was part of the numerical SNe calculation. It was not. That row and the G279 overview map are now
repaired. This is a documentation correction, not a physics change.

So the honest current state is: the reciprocal kernel is intact; the observational bridge is
clearly imported; and the unresolved problem is whether the downstream SNe area curve can be made
independent of the numerical representation without choosing a favorite resolution.
