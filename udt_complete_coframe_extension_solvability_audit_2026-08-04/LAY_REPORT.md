# Lay report

We tested whether the missing bootstrap rule might already be hiding in the ordinary mathematics of
assembling the UDT metric into one complete universe.

It is not hiding in the smooth assembly rules we tested.

Think of the metric's local pieces as panels in a large structure. The joining instructions tell us
how each panel must line up with its neighbors. They are real constraints: a panel cannot be attached
with the wrong orientation or seam data. But once the correct joining instructions are supplied,
every allowed interior design still fits. The joining rules do not choose which interior design the
universe uses.

The same applies to the Cartan connection. Given a complete metric panel arrangement, the geometry
uniquely tells us how to calculate its connection—like calculating the angles and turns in the
assembled structure. That calculation works for every smooth arrangement. It does not say which
arrangement is physically realized.

Holonomy can become selective if we additionally demand that some object return completely
unchanged after being carried around a loop. Our exact examples show that this can leave two, one,
or no allowed directions. But “must return unchanged” is an extra parallelism requirement. UDT's
current observer-pair framework also allows path-labelled comparisons, so that extra rule has not
been derived.

Finally, asking whether a physical equation has solutions cannot tell us what the equation is. We
must first possess the bulk equation and its boundary rule. Using a familiar or conditional equation
to define solvability would merely test that equation; it would not derive the native UDT law.

So the table leg is more sharply located. Smooth global assembly and geometric identities supply the
container and wiring, but not the rule deciding which complete interior is realized. A genuine
metric-native obstruction may still live where the smooth reciprocal split changes rank or breaks
down, but that territory has not yet been mapped as a complete stratified extension problem.
