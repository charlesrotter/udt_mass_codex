## 1. Three objects that must not be conflated

Let `X` be one complete admitted metric/coframe configuration, including whatever slice, observer,
path, boundary, corner, gluing, modulus, and completion data an output needs.

There are three logically different maps:

1. a geometric readout `R_geom[X]` that computes data from a supplied configuration;
2. a physical projection that says which readouts, arguments, and normalizations constitute the
   global state `O`; and
3. a return operation `A(X,O)=0` that restricts which configurations are realized when the global
   data are fed back into local admissibility.

The metric supplies a substantial part of (1). It does not currently supply complete versions of
(2) or (3). Calling all metric-derived objects a vector does not repair that distinction: local
tensors, path-labelled transports, discrete topology labels, conditional integrals, and queried
suprema have different domains and variation types.

## 3. Readout alone is not bootstrap

The exact finite-dimensional control in `ALGEBRA_RESULT.json` uses

```text
R: Q^3 -> Q^2,
R(x1,x2,x3) = (x1+2x2, x2+x3).
```

Introducing independent output coordinates `o` gives the graph constraint

```text
C(x,o) = o-R(x) = 0.
```

Its Jacobian is

```text
[-1 -2  0 | 1 0]
[ 0 -1 -1 | 0 1].
```

It has rank `2` and nullity `3`, exactly the dimension of `x`. For every `x`, choosing `o=R(x)`
solves the constraint. The graph records what the configuration says about itself; it selects no
configuration.

The same `R` is compatible with inequivalent return operations. On four exact witnesses:

- `A_all=0` leaves all four;
- `A_identity=x` leaves only the zero witness; and
- `A_plane=(0,0,x3)` leaves three.

These are logic controls, not proposed UDT laws. They prove the load-bearing point: `R` does not
determine `A`. A return law must have independent native provenance.
