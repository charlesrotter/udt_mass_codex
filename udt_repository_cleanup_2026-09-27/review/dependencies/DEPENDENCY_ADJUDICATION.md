## Reusable classifier

For each actual candidate, apply these checks in order:

1. Preserve explicit protected paths, canonical authority, the three fixed rehearsal paths, current startup/method interfaces and retained numerical packages. Metadata retention is a completed maintenance disposition, not a claim of scientific content review.
2. Read a proposed archive document fully. Decide whether it is a completed administrative record, a maintained source, a receipt, or part of a coherent evidence package. Filename age, a `DISPATCH` suffix or an old branch name does not decide eligibility.
3. Search its exact old path/basename in tracked text, including extensionless hash manifests and `.sha256` files. Classify every discovered kind: executable read/import/output, maintained navigation, working-tree hash pin, fixed-Git snapshot, quoted command/history, inventory-only identity, or an unresolved dynamic consumer. A hit inside a Python docstring is not an executed read. A hit in a manifest is unresolved until its consumer is examined.
4. Trace actual consumers. A reader of `ROOT / row['path']` can bind the working-tree address. A reader of `git show BASE:path` or `git cat-file blob <oid>` binds historical bytes. A verifier comparing two fixed tables may bind only those tables. Preserve fixed tables, source versions and scientific labels in all cases.
5. A cleared move needs byte identity with the baseline Git blob, an explicit old-to-new map, unchanged historical records, maintained links updated only where necessary, and restoration instructions. A path-only adapter must preserve the old verification predicate and source pin; removing a guard to enable movement is not acceptable.
6. Recheck the final diff and exact inventory, exercise relevant guards and failed-input controls, and perform fresh-reader retrieval. A bounded static search cannot establish that all dynamic references in all historical scripts were exhausted. Retain unresolved source interfaces where adaptation would expand this maintenance scope.
