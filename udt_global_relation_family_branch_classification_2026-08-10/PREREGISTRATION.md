# Preregistration — global relation-family ownership across complete metric branches

Date: 2026-08-10
Mode: metric-led, CPU-only, exact/type/provenance classification
Base: `e44b6739`

## Whole question

Across the already mapped complete UDT metric/completion branches, what global observer-relation
family is actually supported by each branch's banked data?

Every declared branch is to be classified without preferring a particle, cosmology, path-independent
answer, zero holonomy, smooth cap, periodic completion, or scalar `phi` potential.

## Frozen outcomes

Each branch receives exactly one primary disposition:

1. `COMMON_CALIBRATED_ATLAS_OWNED` — genuine common charts and triple-overlap descent are supplied;
2. `PATH_BRANCH_GROUPOID_OWNED` — branch/path-labelled arrows and their composition are supplied,
   with nontrivial holonomy allowed;
3. `STRATIFIED_MIXTURE_OWNED` — different regular strata support different owned family types and
   the transition/failure strata are explicit;
4. `LOCAL_RELATIONS_GLOBAL_OWNERSHIP_OPEN` — local pair objects exist, but a complete compatible
   global family or the required middle transitions are not supplied;
5. `NO_COMPLETE_FAMILY_ON_DECLARED_BRANCH` — the declared branch is rank-degenerate, globally
   inconsistent, empty, or explicitly lacks the needed overlap family;
6. `HISTORICAL_PREMISES_CHANGED_REVIEW_REQUIRED` — the branch result depends load-bearingly on a
   premise superseded by the current registry, so it cannot be reused without rederivation; or
7. `INSUFFICIENT_TYPED_EVIDENCE` — the package does not contain enough typed data to adjudicate.

These are provenance/structure classifications, not merit rankings.

## Required fields per branch

- stable branch identity and source package;
- branch/completion geometry and declared domain;
- local observer-query object type;
- transition or path-arrow type;
- overlap domain and rank;
- middle-state ownership;
- triangle/loop return and its interpretation;
- angular/mixing retention;
- seam, cut-locus, null, orientation, and degeneration handling;
- scalar reciprocal reduction status;
- current-premise compatibility;
- primary disposition, caveat, and exact evidence citation.

## Scope and exclusions

The source-package universe is frozen in `SOURCE_PACKAGE_UNIVERSE.tsv`. Generated records may not
alter that universe. The protected untracked curvature-atlas directory is excluded and must not be
read, cited, staged, or modified.

No action, source, carrier, matter, mass, boundary functional, bootstrap optimizer, numerical
`X_max`, CMB spectrum, signal law, preferred congruence, preferred connection, new scalar, GPU
solve, or canon statement is in scope.

## Falsification and certification

The audit fails closed if it:

- silently identifies separately rebuilt middle states;
- calls matrix associativity path independence;
- forces a nonidentity loop to zero;
- infers a scalar character from a general mixing matrix;
- discards a branch for being nonsmooth, nonparticle-like, nonperiodic, or observationally unwanted;
- treats historical strong CSN, a carrier, a boundary, or an action as current authority;
- omits or duplicates a frozen branch identity;
- reads the protected curvature atlas; or
- claims more than the frozen sources type-check.

Certification requires a deterministic complete branch ledger, exact algebraic controls for every
load-bearing transition claim, an independent implementation, a fresh adversarial semantic review,
all current premise/startup gates, six frozen manifests, current paths/frontier targets, and the
documented test baseline.

Maximum conclusion: classification of global relation-family structures supported by the frozen
complete-branch evidence. No physical family selection follows.
